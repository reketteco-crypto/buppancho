# 物販帳のレビュー手順

更新日：2026-11-15。

## 読む資料

1. [現行仕様](../spec/current-spec.md)：業務上期待する動作の正本。
2. [検証状況](validation.md)：実装・自動検証・実機受入・正式利用の到達点と未確認事項。
3. [開発規約](../AGENTS.md)：データ保全、金額、認証、競合、検証の制約。
4. [README](../README.md)：起動方法。運用を確認する場合は [バックアップ・復元](backup-restore.md) と [更新・切り戻し](update-rollback.md) も読む。

業務仕様の判断は現行仕様書へ集約する。コードと試験は実際の動作・検証範囲を確認する資料として扱い、コードに存在することだけで望ましい仕様としない。

## 対象を固定する

ローカルの未コミット・未追跡ファイルを含む対象一覧とファイルハッシュを記録する。GitHubやHEADのみを対象にすると作業中の実装が漏れるため、レビュー対象を明記する。資料・コード・DB制約・画面・試験記録が同じ対象を指すか確認する。

ファイルを渡す場合は対象機能だけでなく共通保存・認証・原価・DB制約も含める。秘密情報、Cookie、環境ファイル、鍵、実DB、個人の実取引は含めない。

## 確認する順序

1. 仕様と範囲の一貫性。
2. 購入→受取→販売→決済の通常操作と、各時点の数量・原価・利益・残高。
3. 後日費用、返品・返金、取消、日付訂正、資材使用の追加。
4. 本人立替・カード、年度・帰属・ロック、同時操作・再送・結果不明。
5. PC／スマホ、キーボード、検索・一覧復帰、実機での入力負担。

最初の依頼では修正を実行せず、再現条件と根拠を持つ指摘を出す。修正時は該当経路を再現・検証する。

## 代表的な操作例

以下は仕様から導くレビュー用の架空例であり、新しく試験を実行した証拠ではない。各例を独立した入力先・データで確認する。

| 要件        | 入力・操作                                                                              | 期待結果                                                                                     |
| ----------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| PUR・STK    | 数量商品10個を総額1,000円、追加費用なし、受取済み・未払いで保存                         | 数量10、管理原価1,000円。口座残高の変化なし                                                  |
| SALE・MONEY | 上記在庫から1個を500円で販売。手数料50円・送料100円、資材なし、受取前                   | 数量9、在庫原価900円、商品別利益250円。口座残高の変化なし                                    |
| MONEY       | 費用差引後350円を受取口座へ記録                                                         | 口座＋350円。数量・商品別利益は変化なし                                                      |
| SALE        | 販売した1個を良品返品。売上返金500円・手数料返還50円・送料返還0円を確認し、決済は未記録 | 販売可能数量10、元の有効原価100円を戻す。口座への反映は実際の返金・返還の記録時              |
| SALE・SAVE  | 返金額が未確認のまま返品入力を途中保存                                                  | 下書きのみ。在庫と返金を確定しない                                                           |
| MAT・REPORT | 資材購入1,000円を記録し、販売で100円分使用                                              | 商品別利益に100円配賦。事業の資材購入費用へ100円を再加算せず、使用だけでは出金しない         |
| MONEY       | 振替9,800円、手数料200円                                                                | 元口座−10,000円、先口座＋9,800円、費用200円を同時記録                                        |
| MONEY       | 本人立替10,000円を4,000円、6,000円で精算                                                | 充当内訳と元支払を保持し、未精算0円。通常口座に内部精算台帳を混ぜない                        |
| PUR         | ファイル取込後に登録商品を選び直す                                                      | 名称・商品ID・計量値を反映し、入力済み価格・数量・通貨・換算・費用・支払を保持。元名称も保存 |
| CTX・SAVE   | 別部門のID、古い設定版、ロック年度で保存                                                | 境界・版・年度を再検証して拒否し、手元入力を保持。部分的な業務確定なし                       |
| SAVE        | 保存直後に応答だけが失われる                                                            | 元要求を照会し、保存済みなら同じ結果を返す。二重出庫・二重決済なし                           |
| MONEY・UI   | 入出金履歴の2ページ目から詳細・取消・結果照会を行う                                     | 元の期間・口座・ページ・位置へ復帰。外部や別画面を保存後の復帰先にできない                   |

## 指摘の形式

- 重大度と短い見出し。
- 対応する現行仕様の章・要件ID。
- 根拠のコード位置・画面・DB制約。
- 再現する入力・状態・操作。
- 期待する動作と実際の動作、その影響。
- 確認済み不具合／未検証の懸念／使い勝手の提案の区別。
- 修正案と必要な検証。未確認なら必要な追加情報。
